# مراجعة تجربة الاستخدام — BunnList (منظور مصمم منتجات iOS)

مرجع: BunnList 2.3 · القاعدة: فرع `main` الحالي.

> **حدود المراجعة:** تمت على مستوى **الكود** في بيئة Linux سحابية — **لم أشغّل Xcode/المحاكي**، فلا ادّعاء باختبار بصري. التحقق البصري يتم على جهازك. اختبارات `BunnListCore` تمر على Linux (109 اختبار).

| الطبقة | الحالة |

## ب. أهم مشكلات الاستخدام (مرتّبة بالأثر)

### 🔴 1. المحتوى الأساسي تجريبي — والقهوة الحقيقية مخبّأة
- **الدليل:** `BunnList/App/AppModel.swift:42` → `catalog = try Catalog.bundledSample()`. كل «اكتشف» و«مجموعتي» و«مسح» تعمل على الدليل التجريبي المحلي. القهوة الحقيقية من الخادم تظهر **فقط** خلف زر ☁️ في `DiscoverView.swift` (`LiveCatalogView`).
- **المرجع:** «اجعل المحاصيل المنشورة هي المحتوى الأساسي. افصل البيانات التجريبية بوضوح، ولا تعرضها تلقائيًا».
- **الأثر:** التجريبي ليس حتى «احتياطيًا عند الفشل» — هو **الافتراضي**. المستخدم يرى أسماء توضيحية بدل قهوته الحقيقية.
- **الاتجاه:** اجعل محتوى «اكتشف» الأساسي هو مَحاصيل الخادم؛ التجريبي يُوسَم بوضوح أو يُخفى خارج وضع التطوير.

### 🔴 2. الحلقة الأساسية **مقطوعة** عبر حاجز تجريبي/خادم
- **الدليل:** التجارب (`ExperienceEditor`) والوصفات (`RecipeEditor`) ترتبط بمحاصيل الدليل التجريبي عبر `model.collect`/`model.book` (محلي). بينما مجموعة الخادم (C07) ومحاصيله الحيّة منفصلة تمامًا.
- **الأثر:** تقدر **تجمع** قهوة حقيقية، لكن **ما تقدر تحضّرها ولا تسجّل تجربتها ولا تسوّي لها وصفة** — لأن هذي المسارات محليّة فقط. فالحلقة «اكتشاف ← جمع ← تحضير ← تسجيل ← تكرار» **ما تكتمل على القهوة الحقيقية**.
- **الاتجاه:** توحيد الحلقة على محاصيل الخادم (قرار مؤسِّس — يتجاوز «تلميع واجهات»؛ أضعه كقرار صريح لك).

### 🟠 3. «مجموعتي» تعرض عالمَين مربكَين
- **الدليل:** `CollectionView.swift` — قسم «محفوظة في حسابك» (خادم) + «على هذا الجهاز (تجريبي)» (محلي). قائمتان للمجموعة.
- **المرجع:** «سهّل الوصول للقهوة المستخدمة حاليًا وآخر وصفة ناجحة». حاليًا لا يوجد مفهوم «قيد الاستخدام» ولا ربط بآخر وصفة.
- **الاتجاه:** مجموعة واحدة (الخادم)، مع «قيد التحضير الآن» + «آخر تحضير ناجح» لكل قهوة.

### 🟠 4. صورة الكيس تُقَص
- **الدليل:** `LiveLotDetailView.swift` → الهيرو `scaledToFill()` + `frame(height: 160)` + قصّ ضمني. يقص المعلومات المطبوعة.
- **المرجع:** «اعرض صورة الكيس كاملة دون قص المعلومات المطبوعة».
- **الاتجاه:** `scaledToFit` بنسبة الكيس، أو ضغطة للتكبير.

### 🟠 5. مساران للمسح متعارضان
- **الدليل:** `ScanView` فيه مسار الاستخراج التجريبي (`SampleBagExtractor` → دليل محلي)، وفوقه زر «ابحث وأضف من الخادم» (شاشة ثانية). مسار OCR الجديد في فرع غير مدموج.
- **المرجع:** «ميّز بين: لا كاميرا، الإذن مرفوض، فشل الاستخراج، لا تطابق. مسار يدوي واضح، ومراجعة قبل الحفظ».
- **الاتجاه:** مسار مسح **واحد** يخدم الخادم: صوّر/اختر → قراءة → مراجعة → تطابق أو اقتراح. حالات واضحة. دمج المسارين.

### 🟡 6. بحث/فلاتر «اكتشف» على التجريبي فقط
- `DiscoverView.swift` — البحث و`FilterMenu` يعتمدان أكواد الدليل التجريبي. محاصيل الخادم بلا بحث/فلاتر في الشاشة الرئيسية (البحث موجود فقط في شاشة «أضف»). المرجع يطلب أولوية البحث والفلاتر مع حالات تحميل/فراغ/خطأ.

### 🟡 7. إتاحة الوصول (Accessibility)
- بطاقات الإحصاء (`AccountView.StatTile`, `JourneysView`) تستخدم `caption2/title3` ثابتة — تنكسر مع Dynamic Type المكبّر. شرائح النصوص الأفقية قد تُقَص. يُنصح: `ScrollView` مرن، أحجام نصوص دلالية، اختبار VoiceOver على الأزرار الأساسية. (الأساس جيد — أغلب الأزرار لها `accessibilityIdentifier`.)

## ج. أفضل ٣ أفكار تنافسية (أبسط نسخة قابلة للاختبار — **بلا تغيير نموذج/خادم**)

### 1) «كرّر أفضل كوب» ⭐
- **المشكلة:** المستخدم يضبط تحضيرًا ممتازًا مرة ثم ينساه.
- **لماذا يتميّز:** يحوّل التطبيق من «أرشيف» إلى «أداة يومية» — القيمة تتكرر كل صباح.
- **أبسط نسخة:** في تفاصيل القهوة، زر «كرّر أفضل تحضير» يفتح `ExperienceEditor` **معبّأً** من أعلى تجربة سابقة (نفس الطريقة/النجوم). يعتمد على التجارب المحلية الموجودة — بلا خادم.

### 2) مقارنة تحضيرين (A/B)
- **المشكلة:** صعب معرفة أثر تغيير متغيّر واحد (طحن/حرارة/نسبة).
- **لماذا يتميّز:** يعلّم المستخدم ويعمّق ارتباطه بالقهوة المختصة.
- **أبسط نسخة:** شاشة تعرض تجربتين لنفس المحصول جنبًا لجنب (الطريقة، الجرعة، الناتج، النجوم). قراءة فقط من التجارب الموجودة.

### 3) «ذائقتك» — ملخص ذوق شخصي
- **المشكلة:** لا يرى المستخدم نمطه عبر الوقت.
- **لماذا يتميّز:** ملخص شخصي يحفّز الاستمرار والمشاركة.
- **أبسط نسخة:** بطاقة في «ملفي/حسابي» تُحسب محليًا: الطريقة الأكثر استخدامًا، المنشأ المفضّل، متوسط نجوم تجاربك. من بيانات التجارب/المجموعة الحالية.

## د. خطة التنفيذ المقترحة (دفعات صغيرة، بعد قرارك)
1. **قرار مؤسِّس:** توحيد المحتوى على الخادم (المشكلتان 1 و2) — يتجاوز «تلميع الواجهات»، فهو قرارك.
2. دفعات واجهات مستقلة وصغيرة: صورة التفاصيل (4) → حالات اكتشف/بحث (1،6) → توحيد المسح (5) → تبسيط مجموعتي (3) → إتاحة الوصول (7).
3. لكل دفعة: فرع مستقل، اختبارات Core تمر، وأنت تتحقق على المحاكي.

> **تعارض يحتاج قرارك:** تنقّل المرجع (المجتمع + حسابي) يختلف عمّا بنيناه (رحلتك + ملفي). لم أغيّر شيئًا — ينتظر قرارك.
